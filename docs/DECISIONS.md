### 데이터 관찰 (1일차)

<!-- 공격 시나리오 하나의 기록을 시간순으로. pid → ppid 족보 -->

**데이터셋:** `python -m soc.simulator.run --dump data/sim.jsonl` → 기록 3,161건, 정답 라벨 14건.
종류별 개수는 process 1,604 · network 1,233 · file 318 · script 4 · registry 2.

**시나리오: `credential_dump` (sc-003, WS-006)**

| 시각       | event_id     | 종류    | 내용                                                                                                                 |
| ---------- | ------------ | ------- | -------------------------------------------------------------------------------------------------------------------- |
| 09:41:42.9 | evt-00003002 | process | `cmd.exe` pid=37467, ppid=1653 (부모 `explorer.exe`)                                                                 |
| 09:41:43.9 | evt-00003003 | process | `rundll32.exe` pid=51765, ppid=37467 (부모 `cmd.exe`), 명령줄 `comsvcs.dll, MiniDump 668 C:\Windows\Temp\d.dmp full` |
| 09:41:44.9 | evt-00003004 | file    | pid=51765가 `C:\Windows\Temp\d.dmp` create                                                                           |

**족보 (`pid` → `ppid`)**

```
rundll32.exe (pid 51765) ← ppid 37467
  └ cmd.exe (pid 37467) ← ppid 1653
      └ 1653 = explorer.exe (생성 기록 없음, 족보가 여기서 끊김)
```

부모는 같은 `host` 이고 자식보다 이전 시각인 `process` 기록에서 찾을 수 있었음.

**알게 된 것**

1. 다른 PC에 같은 pid가 21개 있음 (예: pid 24506은 WS-006과 WS-003). `host` 없이 부모를 찾으면 엉뚱한 PC의 프로세스가 섞이게 됨.
2. WS-006에서 `credential_dump`가 두 번 있음 (sc-003 09:41 user=cho, sc-004 09:27 user=kim). 둘 다 `d.dmp`를 같은 경로에 만들어서 `get_host_timeline`으로 보면 사건이 섞일 수 있어 `pid`와 `user`로 가름.
3. `rundll32.exe`는 `signed=True`임. 서명 여부만으로는 악성을 가를 수 없고, 명령줄(`MiniDump`)과 부모가 근거가 됨.
4. `cmd.exe`의 부모(`explorer.exe`)는 `parent_name`으로 이름은 알지만 생성 기록이 없음. 도구는 이 경우 `note`로 알려 줘야 함.

### text vs keyword (1일차)

<!-- 03 문서 1장의 질문에 대한 내 답과, 실제로 정한 매핑 -->

**질문:** 호스트 이름(`WS-007`)은 `text`와 `keyword` 중 무엇으로 저장해야 하나? 왜?

**답:** `keyword`. 호스트 이름은 쪼개서 찾을 말이 아니라 통째로 정확히 같은지 확인하는 값이다. `text`는 저장할 때 분석기가 소문자로 바꾸고 단어로 쪼개므로 `WS-007`이 `ws`, `007`로 나뉜다. 조사 도구는 `host`와 `pid`가 같은 기록을 찾는 것이라 `term` 조회가 정확히 맞아야 하고, 다른 PC가 섞이면 안 된다.

**직접 확인한 결과** (진짜 OpenSearch, 기록 3,161건)

| 쿼리                                     | 결과  | 알 수 있는 것                                  |
| ---------------------------------------- | ----- | ---------------------------------------------- |
| `host` term `WS-006`                     | 349건 | keyword는 통째로 일치                          |
| `host` term `ws-006` (소문자)            | 0건   | keyword는 대소문자도 구분                      |
| `cmdline`(text) match `MiniDump`         | 4건   | text는 단어 단위로 전문 검색                   |
| `cmdline`(text) term `MiniDump` (대문자) | 0건   | text는 소문자로 저장되어 대문자 term은 못 찾음 |
| `cmdline`(text) term `minidump` (소문자) | 4건   | 위와 같은 이유                                 |
| `cmdline.keyword` term `cmd.exe`         | 6건   | 명령줄 전체가 같을 때만 일치                   |
| `cmdline.keyword` term `MiniDump`        | 0건   | keyword는 부분 일치가 안 됨                    |

**정한 매핑**

| 칸                                                                | 타입                      | 이유                                                  |
| ----------------------------------------------------------------- | ------------------------- | ----------------------------------------------------- |
| `host`, `type`, `event_id`, `process.name`, `parent_name`, `user` | keyword                   | 정확히 일치로 거르는 값                               |
| `process.cmdline`, `script_text`                                  | text + keyword (`fields`) | 단어 검색(`MiniDump`)과 정확 일치·집계를 둘 다 하려고 |
| `ts`                                                              | date                      | 시간 범위(`range`) 검색                               |
| pid, ppid, 포트, 바이트                                           | long                      | 숫자 비교                                             |
| `network.dst_ip`                                                  | ip                        | IP 형식 검증과 대역 검색                              |

**포기한 것 / 주의**

- 명령줄을 text와 keyword로 둘 다 두면 색인 크기가 늘어난다. 대신 검색 방식이 두 가지가 된다.
- `ignore_above`(명령줄 4096, 스크립트 8191)를 넘는 값은 keyword로 색인되지 않아 정확 일치에서 빠진다(오류는 아님). text로는 계속 검색된다.
- `dynamic: strict`라서 매핑에 없는 칸이 오면 기록이 거절된다. 처음에 매핑이 비어 있을 때 25건이 모두 거절됐다. 새 칸이 생기면 템플릿을 먼저 고쳐야 한다.
